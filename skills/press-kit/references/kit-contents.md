# Kit contents

`<name>` is the brand slug (`manifest.name`), lowercase. Themes: every still and loop exists in
`dark` and `light`; add brand colourways where they make sense (an accent-colour avatar, for
instance).

## Logos: `public/press/logos/`

Each logo is one outlined SVG plus PNG rasters on a transparent ground. PNG sizes are the long side.

| File | Variants | PNG sizes | Notes |
|---|---|---|---|
| `<name>-mark-<colourway>` | each brand colourway (ink, paper, accent) | 512, 1024 | The symbol alone |
| `<name>-wordmark-on-dark`, `-on-light` | 2 | 1024, 2048 | Text outlined to paths |
| `<name>-lockup-on-dark`, `-on-light` | 2 | 1024, 2048 | Mark + wordmark |
| `<name>-avatar-<colourway>` | each colourway | 400, 1024 | Square, full bleed, survives a circular crop |
| `<name>-app-icon-<colourway>` | each colourway | 192, 512, 1024 | Square tile |

Files: `<id>.svg`, `<id>-<px>.png` (for example `acme-lockup-on-dark-2048.png`).

## Posts: `public/press/posts/`

| Id | Size (px) | Use |
|---|---|---|
| `x-<nn>-<slug>` | 1500 × 900 | One image per X post, numbered as a series |

1500 × 900 (5:3) is the working default: it matches the post loops, so an image and its video are
interchangeable. 1200 × 675 (16:9) and 1080 × 1350 (portrait) are valid alternatives; pick one
per series and keep it.

## Motion: `public/press/motion/`

| Id | Size (px) | Length | Use |
|---|---|---|---|
| `mx-<slug>` | 1500 × 900 | 6 to 12 s loop | One idea per loop, pairs with a post |
| `motion-banner` | 1500 × 500 | 8 to 12 s loop | Animated header |
| `<name>-film` (optional) | 1920 × 1080 | 20 to 45 s | Promo film, several scenes on one timeline |

Per loop: `<id>-<theme>.mp4` (H.264 High, yuv420p, 30 fps, native size, no audio), `<id>-<theme>.png`
(the poster: the frame at `hold`, the composed moment), optional `<id>-<theme>.gif` for the mark
(about 800 px wide, 15 fps).

## File naming

- Stills and loops: `<id>-<theme>.png`, `<id>-<theme>@2x.png`, `<id>-<theme>.mp4`.
- `@2x` is the same composition at twice the pixel density (3000 × 1000 for an X header). It is
  rendered, not upscaled.
- Width and height must be even numbers for anything that becomes video.

README.txt is generated by a studio route from the same data as the press page, so it never
drifts. No font files unless the licence allows redistribution: name the fonts and link to them.

## The press page: `/press-kit`

One long page, a spec sheet more than a marketing page. Chapters, in order, each with an anchor:

1. **About**: tagline, one-liner, boilerplates in three lengths, each with a copy button. Name
   forms: how to write the name, and the wrong spellings to avoid.
2. **Facts**: a table of what can be stated, each fact with its value and a note; items not live
   yet marked "soon".
3. **Logo**: every logo file on its intended ground, with SVG and PNG download links, clear space
   and minimum size.
4. **Colour**: tokens grouped by role, each with name, hex, OKLCH and CSS variable, click to copy.
   Contrast pairs with their measured ratio.
5. **Type**: families, roles, weights, licence, and the type scale set in the real fonts.
6. **Usage**: dos and don'ts, shown as examples where possible.
7. **Assets**: banners, social and post images read from `public/press`, each with its pixel size,
   file size, and 1x / @2x download.
8. **Motion**: each loop playing (poster under reduced motion), with MP4 / GIF download.
9. **Contact**: press contact, and the ZIP download with its size, date and file count.

The page reads `public/press` on the server at render time (see the reader skeleton in
`studio-contract.md`), so it lists what was actually rendered. Give it its own Open Graph image.
Decide with the user whether it is linked in the footer or shared by link only (`noindex`).
